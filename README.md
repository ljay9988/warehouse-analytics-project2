## Project Warehouse analytics Overview
Project Warehouse Analytics analyses the DataCo Supply Chain Dataset to investigate shipping performance, delivery reliability, product and category patterns, customer geography, and factors associated with late delivery risk.

The project follows a complete data analytics workflow:

ETL - Exploratory Data Analysis - Statistical Analysis - Machine Learning - Power BI Dashboard

The overall objective is to transform a large raw supply-chain dataset into a clean, reproducible dataset, investigate business questions using statistical and visual analysis, develop a predictive machine learning model, and communicate the findings through an interactive Power BI dashboard.

## Dataset Content
This project uses the DataCo Supply Chain Dataset, a large real-world supply-chain dataset containing information about:

- Order information
- Shipping details
- Delivery status
- Product information
- Customer information
- Customer location
- Order values
- Shipping dates
- Scheduled and actual shipping times

The original dataset contains approximately 180,519 orders.

The raw dataset is stored locally at:

data/raw/DataCoSupplyChainDataset.csv

The cleaned dataset generated by the ETL pipeline exceeded 100 MB, which caused GitHub to reject the file because it exceeded the standard GitHub file-size limit.

To resolve this:
The cleaned dataset was added to .gitignore.
The previously tracked cleaned dataset was removed from Git tracking using:
git rm --cached data/cleaned/dataco_cleaned.csv
The cleaned dataset is now generated locally by the ETL pipeline.

This means the repository contains the reproducible code required to generate the cleaned dataset, rather than storing the large generated file in GitHub.

The cleaned dataset is generated at:

data/cleaned/dataco_cleaned.csv

## Business Requirements
1. analyse delivery performance across all orders
- identify how many deliveries are late vs on time
- understand factors contributing to late deliveries
- measure the difference between scheduled and actual shipping days
2. Evaluate the impact of shipping mode on delivery outcomes
- compare late delivery risk across different shipping modes
- determine which shipping methods are most reliable
- highlight modes that consistently underperform
3. prepare a clean, structured datset for future modelling and dashboarding
- ensure the ETL pipeline produces a reproducible cleaned dataset
- enable future predictive modelling (e.g preedicting late deliveries)
- support future dashboard development for operational monitoring


## Hypothesis
1. shipping mode affects the likelyhood of late delivery.
- group orders by 'shipping_mode
- calculate the percentage of late deliveries
- compare modes using bar charts and summary statistics
2. Orders placed during different months have different late delivery rates
- Group orders by `order_month`
- Calculate the late delivery rate for each month
- Compare monthly late delivery rates
- Visualise the results using a bar chart
3. Certain product categories have different late delivery rates
- Group orders by `category_name`
- Calculate the percentage of late deliveries for each category
- Compare the categories using a bar chart
4. Customer country is associated with late delivery risk
- Group orders by `customer_country`
- Calculate the percentage of late deliveries for each country
- Compare the countries using a bar chart
- Evaluate whether the difference is meaningful based on the results
5. High-value orders are more likely to be delivered late

- Compare late delivery rates between high-value and regular orders
- Visualise the results using a bar chart
- Evaluate whether there is a meaningful difference between the two groups

## Data Management
The data was managed through a reproducible ETL pipeline.

The pipeline:

Reads the raw CSV file.
Standardises column names.
Converts date fields to datetime values.
Handles the small number of missing values.
Creates analytical features.
Saves the resulting cleaned dataset.

The ETL pipeline is implemented in:

src/etl_pipeline.py

This approach means that the cleaned dataset can be recreated rather than relying on manually edited data.
## Analysis techniques 
The following analysis techniques were used in the project:

Descriptive statistics, including mean, median, mode, variance and standard deviation.
Probability calculations to measure the proportion of late deliveries.
Grouping and comparison of delivery outcomes across shipping modes, months, product categories, customer countries and order-value groups.
Feature engineering to create variables used for analysis and modelling.
Plotly visualisations, including bar charts and box plots.
A Decision Tree Classifier for predicting late_delivery_risk.
An 80/20 training and testing split for the machine learning model.
Model evaluation using accuracy, precision, recall, F1-score and a confusion matrix.
Feature importance analysis to identify which variables the Decision Tree relied on most heavily.
Investigation and removal of potential data leakage before evaluating the final model.
Limitations

The dataset limited the analysis in several ways. Geographic analysis was restricted because only a small number of customer-country groups were available. Some shipping-mode results were also unusual and required cautious interpretation.

The final machine learning model achieved 69.63% accuracy and had 54% recall for the At Risk class, meaning that a substantial number of genuinely at-risk orders were not identified.

## Dashboard
The project contains a two-page Power BI dashboard designed to communicate the main findings from the analysis.

## Page 1 — Supply Chain Delivery Risk Dashboard

Page 1 focuses on operational delivery performance.

The page contains:

Overall Late Delivery Risk KPI.
Total Orders KPI.
Late Delivery Risk by Shipping Mode chart.
Late Delivery Risk by Month chart.
Late Delivery Risk by Product Category chart.
Late Delivery Risk: High-Value vs Regular Orders chart.

The visuals were selected to provide a concise overview of the main delivery patterns identified during the EDA.

The dashboard also supports interactive cross-filtering. Selecting a category or shipping mode in a visual updates the other visuals, allowing users to explore relationships within the dataset.

## Page 2 — Machine Learning Results

Page 2 focuses on the performance and interpretation of the machine learning model.

The page contains:

Model Accuracy KPI.
At Risk Precision KPI.
At Risk Recall KPI.
Confusion Matrix.
Top Features Used by the Model.

This page separates the technical machine learning results from the operational dashboard so that users can focus on either business insights or model performance.

The dashboard was designed for both technical and non-technical audiences.

For non-technical users, Page 1 focuses on simple KPIs and visual comparisons. Users can quickly identify differences in delivery risk without needing to understand the underlying Python code or machine learning methodology.

For technical users, Page 2 provides model evaluation information including precision, recall, F1-score information, the confusion matrix and feature importance.

The use of clear titles and a limited number of visuals was intended to avoid overwhelming the user while still providing enough information to investigate the findings.
